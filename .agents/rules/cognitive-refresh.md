# 認知的リフレッシュ・プロトコル (Cognitive Refresh Protocol)

## 1. 目的
本プロトコルは、LLM特有の構造的弱点である「コンテキスト圧迫による忘却（Lost in the Middle）」や「ルールの形骸化」を物理的なアプローチで防ぐための強制ルールです。

## 2. 発動条件（いつ自覚すべきか）
AI（あなた）は、以下の状況に該当する場合、自身がすでに**「ルールの忘却」や「ハーネス（ルールやガイドライン）の形骸化」を引き起こしている状態にあると強く自覚**しなければなりません。

1. `grep`, `glob`, `find`, `cat` などのコマンドやツールを使用し、**巨大な出力（大量の検索結果や巨大なファイル内容）を処理した直後**。
2. 多数のやり取りが積み重なった**長時間のセッション**。
3. 一つの大きなタスクが終わり、**次フェーズ（次のタスク・ステップ）へ移行するタイミング**。
4. 計画立案やタスク実行の**初動フェーズ**。

## 3. なぜリフレッシュが必要なのか（Why）
LLMのアーキテクチャ上、入力トークン（コンテキスト）が長くなると、最初の方に提示された「システムプロンプト」や「厳密なルール」への注意力が著しく低下（Lost in the Middle： 中間情報の忘却現象）します。
過去のインシデントでは、この状態に陥ったAIが、記憶に頼った暗黙的な行動や推測での出力を強行し、「作業前の事前承認（HITL）」や「破壊的操作の禁止」といった絶対ルールをいとも簡単に破棄してシステムを破壊しました。

## 4. 具体的なプロトコル手順（How）
コンテキスト圧迫が懸念されるフェーズにおいて、AIは記憶に頼った行動を**絶対に行わず**、以下の行動をとる必要があります。

- **物理的な再読み込み（Read File）の強制**:  
思考プロセス（Thought）内での自己言及（「ルールを守ろう」と念じること）だけでは不十分です。必ず該当する AI利活用ファイル（`GEMINI.md` や 各種ルールファイル、`task.md`、`implementation_plan.md`）や引継ぎドキュメント（`HANDOVER.md`）を**物理的に再読み込み**し、タスク内容と自身に課された行動指針を正確に脳内にロードし直してから作業を進めてください。
- **セッションリセットの提案**:  
長時間のセッションでコンテキスト圧迫が限界に近い（または限界を超えている）と判断される場合は、ユーザーに「引継ぎドキュメント（`HANDOVER.md`）の作成・更新（[`handover` スキル](../skills/handover/SKILL.md)）」または「バックアップやバージョン履歴の保存処理」を実施した上で、セッションを新しく切り替える（New Chat）ことを**提案**してください。
