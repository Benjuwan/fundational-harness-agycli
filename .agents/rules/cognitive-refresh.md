# 認知的リフレッシュ・プロトコル (Cognitive Refresh Protocol)

## 1. 目的
本プロトコルは、LLM特有の構造的弱点である「コンテキスト圧迫による忘却（Lost in the Middle）」や「ルールの形骸化」を物理的なアプローチで防ぐための強制ルールです。

## 2. 発動条件
以下の状況では、§4 の手順で作業の前提を整え直してください。

1. ファイル検索や内容取得などのコマンド・ツールを使用し、**巨大な出力（大量の検索結果や巨大なファイル内容）を処理した直後**。
2. 多数のやり取りが積み重なった**長時間のセッション**。
3. 一つの大きなタスクが終わり、**次フェーズ（次のタスク・ステップ）へ移行するタイミング**。
4. 計画立案やタスク実行の**初動フェーズ**。

## 3. なぜリフレッシュが必要なのか（Why）
コンテキスト圧縮や長い作業の後は、常時ロードされないファイル（計画・進捗・引き継ぎ・条件付きルール）の最新内容が手元にないまま、記憶に頼って判断しやすくなるためです。

## 4. 具体的なプロトコル手順（How）
コンテキスト圧迫が懸念されるフェーズでは、記憶に頼らず以下の行動をとってください。

- **行動指針の再確認**:  
`GEMINI.md` と `trigger: always_on` のルールは常時ロード済みのため、読み直す必要はありません。一方、`tasks/tmp/[CurrentSessionName]_task.md`、`tasks/tmp/[CurrentSessionName]_implementation_plan.md`、引継ぎドキュメント（`HANDOVER.md`）、および `trigger: model_decision` のルール（`output-quality-guidelines.md`、`subagent-policy.md`、`troubleshooting.md`）は常時ロードされないため、圧縮後や新フェーズの開始時に**物理的に読み直してください**。
- **セッションリセットの提案**:  
長時間のセッションでコンテキスト圧迫が限界に近い（または限界を超えている）と判断される場合は、ユーザーに「引継ぎドキュメント（`HANDOVER.md`）の作成・更新（[`handover` スキル](../skills/handover/SKILL.md)）」または「バックアップやバージョン履歴の保存処理」を実施した上で、セッションを新しく切り替える（New Chat）ことを**提案**してください。
