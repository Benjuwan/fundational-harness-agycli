# GA4 インサイト獲得 参考プロンプト集
本ドキュメントは、`bq-analysis` スキルでの分析作業において、接続疎通テスト完了後のファーストステップ、またはユーザーから具体的な分析指示（自然言語）がまだない場合のスタートライン（きっかけ）として提供する参考プロンプト集です。

## 0. 前提メモ（メディア概要ヒアリング）
分析の精度を上げるため、最初に一度だけ以下の情報をユーザーに確認し、以降の分析指示の文脈として利用してください（同一セッション内では再度聞く必要はありません）。

```
【メディア概要】
・メディア名：（例）〇〇コラム
・ターゲット読者：（例）30〜40代の中小企業の経営者
・目的：（例）問い合わせ獲得 / ブランディング
・運営歴：（例）2年、月間3万PV程度
・重視するコンバージョンイベント名：（例）generate_lead, form_submit
・ディレクトリ構成：（例）記事は /column/ 配下、サービス紹介は /service/ 配下
・除外すべきノイズ：（例）Directチャネルにはボットが多いので原則除外
```

## 1. カテゴリ別 分析プロンプト集

### ① 流入元データ：どこからの読者が「本当に読んでくれているか」を知る
```
過去[期間]の流入チャネル別データを抽出し、以下の観点で教えてください：
1. セッション数が多い上位5チャネルと、それぞれのエンゲージメント率とキーイベント率
2. 「セッション数は少ないが、エンゲージメント率が高い」チャネルはありますか？
3. 逆に「セッション数は多いが、エンゲージメント率が低い」チャネルで注意すべきものは？
4. このデータから、今後の集客戦略として考えられることを1〜2点教えてください

結論や改善案はまだ不要です。
```

### ② ページデータ：「読まれているページ」と「読まれていないページ」の違いを探る
```
過去[期間]のページ別データを抽出し、以下を教えてください：
1. 閲覧数上位10ページのタイトルと閲覧数
2. 上位ページに共通するテーマや傾向はありますか？
3. 閲覧数が少ないにもかかわらず、エンゲージメント時間が高いページはありますか？
4. 「このようなテーマの記事をもっと増やすと良さそう」という仮説を立ててください

結論や改善案はまだ不要です。
```

### ③ ユーザー属性データ：読者像と「想定ターゲット」のズレを確認する
```
過去[期間]のユーザー属性データを抽出してください。
私たちのターゲット読者は「[前提メモのターゲット読者]」です。以下を教えてください：
1. 実際の年齢層・性別の分布
2. ターゲットと実際の読者にズレはありますか？
3. このデータをもとに、コンテンツ戦略や記事の書き方で変えるべき点があれば教えてください

結論や改善案はまだ不要です。
```

### ④ コンバージョン・イベントデータ：「成果につながる行動」を起こしているのは誰か
```
過去[期間]のイベントデータを抽出してください。
私たちのメディアの主なコンバージョンは「[前提メモの重視イベント]」です。以下を教えてください：
1. コンバージョン数・コンバージョン率の全体傾向
2. コンバージョンに至ったセッションで多く発生しているイベント（スクロール、クリックなど）はありますか？
3. コンバージョンが少ない、または0に近い状況であれば、考えられる原因を教えてください
4. コンバージョン率を改善するために、まず確認すべき仮説を2〜3個挙げてください

結論や改善案はまだ不要です。
```

### ⑤ 主要導線の棚卸し：表示回数が多いのにエンゲージメントが低いページを探す
```
過去28日間で表示回数の多い上位20ページを抽出してください。
表示回数、エンゲージメント率、平均エンゲージメント時間、キーイベント数を表にまとめ、
表示回数が多いのにエンゲージメント率が全体平均より10ポイント以上低いページに印をつけてください。

結論や改善案はまだ不要です。
```

### ⑥ 新規×リピーター比較：セグメント間の「差」を見つける
```
過去90日間について、新規ユーザーとリピーターを比較してください。
流入チャネル別にセッション数、エンゲージメント率、キーイベント率を並べた表を作り、
両者の差が大きい項目を上位5つまで、差を数字で示してください。

結論や改善案はまだ不要です。
```

### ⑦ イベント推移（週次モニタリング）：重要イベントの変動を追う
```
[重視イベント名]の件数を週ごとに、過去12週分並べてください。
前週比で20%以上動いた週に印をつけてください。

結論や改善案はまだ不要です。
```

## 2. 掘り下げプロンプト集（初回結果を「出発点」にする）
初回の分析結果はあくまで出発点であり、そこから対話を重ねることで具体的なアクションが見えてきます。

```
今の分析で「〇〇」という指摘がありましたが、もう少し具体的に教えてください。
特に、来月すぐに試せる施策として、優先度の高い順に3つ挙げてもらえますか？
```

```
この結果を、Webサイトの担当者ではなく上司（経営者）に報告する場合、
どのようにまとめると伝わりやすいでしょうか？
```

```
[セグメントA]の[ディメンション]別に、[指標]を出してください。
```
（例：「新規の自然検索で、ランディングページ別にキーイベント率を出して。」）

## 3. 分析時の注意点
- **指標定義の明示**: AIが出す数値をうのみにしないよう、分析結果の提示時には「取得に使ったディメンション、指標、期間、フィルタと、各指標の定義」を一言添えるよう徹底してください（例: GA4の直帰率はUA時代の定義と異なり「エンゲージメントのなかったセッションの割合」）。
- **「差」の発見と原因解釈の役割分担**: AIが担うのは数値上の「差」や傾向の発見まで。なぜその差が生まれたのかの原因解釈は、コンテンツや施策を知るユーザー側の判断に委ねてください。
- **改善案は求められるまで出さない**: 「結論や改善案はまだ不要です」と明示すると、AIは提案より先に正確な表・データ整理を優先しやすくなります。
- **ノイズ除外条件の使い回し**: 「Directチャネルにはボットが多いので原則除外」など、メディア固有の除外条件があれば前提メモに含めて毎回使い回してください。

## 4. スキルでの使い方
`bq-analysis` の Step1（初期設定・疎通テスト）完了後、ユーザーの分析したい内容が固まっていない場合は、本ファイルのカテゴリ（①〜⑦）を提示して選んでもらうか、自由記述の指示を受け付けてください。選ばれたプロンプトの `[期間]` `[前提メモの◯◯]` 等のプレースホルダーは、ユーザーとの対話または前提メモの内容で具体化したうえで、通常の自然言語解析（Step2）に渡してください。
