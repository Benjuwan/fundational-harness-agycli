# Handover Skill
このスキルは、これまでの会話内容を次の新しいチャットでそのまま作業を再開できるように、情報漏れのない引き継ぎメモとして整理するために使用されます。

<instructions>

## 目的
要約ではなく、「別チャットのAIがこのメモを読んだだけで、現在のシステム状態と文脈を完全に復元し、シームレスに作業を再開できること」を目的にまとめてください。
重要な背景・会話の経緯・決定事項・未解決事項・関連するファイルパス・エラーログなどを**絶対に省略せず、詳細に記述**してください。

> [!IMPORTANT]
> - `git add`または`git commit`といった git 操作は一切不要  
> 当スキルのスコープはドキュメント作成です。**ユーザーが明示的に指示しない限り**、ドキュメント作成以外の処理や対応は一切不要です。

### 当スキルがスコープとする作成（更新）ファイル
- `HANDOVER.md`（または`[対象プロジェクト名-]HANDOVER.md`）:  
タスクの目的、経緯、決定事項、未解決事項などをまとめた引き継ぎメモ。**記載内容は後述の【出力フォーマット（テンプレート）】を遵守する**こと。

#### ファイルの配置場所
- 親ディレクトリとして作業対象ディレクトリがある場合: 当該作業対象ディレクトリ直下に保存
- 作業対象ディレクトリがない場合: プロジェクトルート直下に保存

## 出力指示
**必ずユーザーに作成または更新の実施を確認してから**以下のMarkdownテンプレートを**そのまま埋める形**で、1つの引き継ぎドキュメント（`HANDOVER.md`）を作成してください。

### 【重要】目的セクションの自律的更新と報告義務
「1. ユーザーの根本課題と最終目的」セクションは、**引き継ぎのコンテキストを維持するための最重要項目**です。
- 対話の中でタスクの前提や目的が大きく変更されたとAI自身が判断した場合は、引継ぎドキュメント作成時にこのセクションの内容も最新の状態に自律的にアップデートしてください。
    - **アップデートを行った場合は、必ずドキュメント出力時（または完了報告時）に「目的セクションの記述を最新の要件に合わせて更新しました」とユーザーへ明確に事後報告すること**が義務付けられています。

### 情報量が多い場合の優先度基準
会話が長く、すべての情報を含めるとドキュメントが肥大化する場合は、以下の優先度順に従って取捨選択すること。低優先度の情報を削る場合は、その旨をドキュメント末尾に明記する。

1. **最優先**: 根本課題と目的、現在の状態・直近のエラー・次のステップ
2. **高優先**: 確定済みの仕様・変更禁止事項
3. **中優先**: 却下されたアプローチとその理由
4. **低優先**: 時系列の詳細な経緯

### 出力フォーマット（テンプレート）

```markdown
# 引き継ぎドキュメント（HANDOVER.md）

## 1. 【絶対遵守】ユーザーの根本課題と最終目的（Core Pains & Goals）

> [!CAUTION]
> 以下の内容はユーザーの初期要件および根本課題です。ユーザーからの明示的な指示がない限り、AIによる要約・削除・改変は固く禁じられています。
- **根本課題**: （ユーザーが提示した生の問題や背景。例: セッションを跨いだ際に目的が薄れる問題）
- **最終目的**: （最終的に達成すべきゴール）

## 2. 現在のコンテキストと前提条件
- **技術スタック**: 言語、フレームワーク、ライブラリなど
- **環境・制約**: 重要なルール、インフラ構成など
- **主要な関連ファイル**: 現在作業中のファイルパスや影響を受ける重要なファイル群、実装計画書（`implementation_xxxx.md`）、タスク進捗ファイル（`task-xxxx.md`または`task-xxxx.log`）の内容またはファイルパス
- **使用したスキルやサブエージェント、参照ファイル**: 今回の作業で使用した主要なスキル群（例: `.agents/skills/<スキル名>/SKILL.md`）やサブエージェント群（例：`.agents/agents/<サブエージェント名>.md`）、参照ファイル群（ドキュメント、画像ファイルなど）

## 3. 進捗と関連リソース
- [ファイルパス例: `tasks/tmp/implementation_plan.md`]
  - 状況: （※最大1行で現在のステータスや概要を記載。長文要約は禁止）
- [※不要になった古いファイルへのリンクは適宜削除（ガベージコレクション）すること]

## 4. ここまでの経緯（タイムライン）
- これまでに実行したこと、試したアプローチ
- 発生したエラーとその原因（分かっている範囲で原文まま）
- 却下されたアイデアや方針（同じ間違いを繰り返さないため）

## 5. 決定事項と確定済みの仕様
- 今後の前提として扱うべき（遵守すべき）ルールや決定事項
- 変更してはいけないコードや仕様

## 6. 現在の状態と未解決事項（Pending）
- **現在の状態**: （例：〇〇の実装までは完了しているが、テストが通らない状態）
- **残タスク・未解決事項**: 次のステップで取り組むべき具体的な課題
- **確認事項**: 不明点や確認不足の点

## 7. 次のAIへの初期プロンプト（依頼文）
> 新しいチャットを開始後、ユーザーがそのまま送信できる、次のアクションを促すための具体的な指示文を記述してください。
> （例：「上記の引き継ぎ内容を確認し、〇〇の作業から再開してください。まずは修正方針の提案をお願いします。」）
```

## 注意事項
- 情報の非可逆圧縮（要約）をしない: コードスニペット・プロンプト案など重要と思われる情報は、「たぶん不要」と判断して削除せず、必ず含めること。情報を必要以上に短く省略しないこと
- エラーログは原文を必ず含める: エラーメッセージは要約・言い換えをせず、原文のままコードブロックで引用すること
- 関連リソースのインライン要約は1行制限とする: 出力の肥大化を防ぐため、ファイルのステータス記載は極力簡潔に行うこと
- 標準的なMarkdownを使用する: 見出しには必ず `#` や `##` などの標準Markdownを利用し、リストや箇条書きを用いて構造化すること
- 推測を含めない: 確定事項と未確認事項（推測）は明確に区別して記載すること
- 曖昧な表現を避ける: 次のチャット単体で再開できる粒度で記述する。「必要に応じて参照」のような丸投げ表現は使わない
- 作業関連の成果物を落とさない: 会話中に登場したプロンプト案・文案・コード方針・記事構成案なども漏れなく含める
- 引継ぎドキュメント（`HANDOVER.md`）作成後、内容のセルフチェック・レビューを行った上でユーザーへ報告する

</instructions>
