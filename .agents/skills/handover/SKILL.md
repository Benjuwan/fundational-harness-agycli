# Handover Skill
このスキルは、これまでの会話内容を次の新しいチャットでそのまま作業を再開できるように、情報漏れのない引き継ぎメモとして整理するために使用されます。

<instructions>

## 目的
要約ではなく、「別チャットのAIがこのメモを読んだだけで、現在の状況と文脈を完全に復元し、シームレスに業務を再開できること」を目的にまとめてください。
重要な背景・会話の経緯・決定事項・未解決事項・関連するファイルパス・直面している課題やエラーなどを**絶対に省略せず、詳細に記述**してください。

> [!IMPORTANT]
> 当スキルのスコープは引き継ぎ用ドキュメントの作成です。**ユーザーが明示的に指示しない限り**、ドキュメント作成以外の処理（余分なファイルの更新や設定変更など）は一切不要です。

## 出力指示
**必ずユーザーに作成または更新の実施を確認してから**以下のMarkdownテンプレートを**そのまま埋める形**で、1つの引き継ぎドキュメント（`HANDOVER.md`）を作成してください。  
- 作業対象のフォルダがある場合: 当該フォルダ直下に保存
- 作業対象のフォルダがない場合: 指定されたベースディレクトリ（ルート）直下に保存

### 情報量が多い場合の優先度基準
会話が長く、すべての情報を含めるとドキュメントが肥大化する場合は、以下の優先度順に従って取捨選択すること。低優先度の情報を削る場合は、その旨をドキュメント末尾に明記する。

1. **最優先**: 現在の作業状態・直近の課題や問題点・次のステップ（セクション5・6）
2. **高優先**: 確定済みのルール・変更禁止事項（セクション4）
3. **中優先**: 却下されたアプローチやアイデアとその理由（セクション3）
4. **低優先**: 時系列の詳細な経緯（セクション3の前半）

### 出力フォーマット（テンプレート）

```markdown
# 引き継ぎドキュメント（HANDOVER.md）

## 1. 目的とゴール
- **当初の目的**: このタスク・チャットで達成しようとしていたこと
- **最終ゴール**: 最終的に期待されている状態や成果物

## 2. 現在のコンテキストと前提条件
- **使用ツール・環境**: 使用しているソフトウェア、ツール、フォーマットなど
- **前提条件・制約**: 重要なルール、業務上の前提事項など
- **主要な関連ファイル**: 現在作業中のファイルや影響を受ける重要な資料群、企画書（`plan_xxxx.md`など）、進行管理ファイル（`task-xxxx.md`など）の内容またはファイルパス
- **使用したスキルやエージェント、参照ファイル**: 今回の作業で使用した主要なスキル群やAIエージェント、参照した資料（ドキュメント、画像ファイル、参考URLなど）

## 3. ここまでの経緯（タイムライン）
- これまでに実行したこと、検討したアイデアやアプローチ
- 発生した問題点・課題（エラーなど）とその原因（分かっている範囲で）
- 却下されたアイデアや方針（同じ間違いを繰り返さないため）

## 4. 決定事項と確定済みのルール
- 今後の前提として扱うべき（遵守すべき）ルールや決定事項
    - AI利活用ファイル（システムプロンプトや各種ルールファイル、「現在のコンテキストと前提条件」で言及した使用スキルファイルや参照ファイル）
    - 今回の作業中に発生した固有の一時ルール、決定事項など
    - 別途ユーザー指示による制約事項
- 変更してはいけないフォーマットや記述、仕様

## 5. 現在の状態と未解決事項（Pending）
- **現在の状態**: （例：〇〇の資料作成までは完了しているが、〇〇の記載内容が確定していない状態）
- **残タスク・未解決事項**: 次のステップで取り組むべき具体的な課題
    - **「企画書」や「進行管理ファイル」がある場合、それらの具体的内容を含めて現在のフェーズ位置（進捗情報）の記載までも忘れず行う**
- **確認事項**: 不明点や確認不足の点

## 6. 次のAIへの初期プロンプト（依頼文）
> 新しいチャットを開始後、ユーザーがそのまま送信できる、次のアクションを促すための具体的な指示文を記述してください。
> （例：「上記の引き継ぎ内容を確認し、〇〇の資料における〇〇の課題への対応から作業を再開してください。まずは今後の進め方の提案をお願いします。」）
```

## 注意事項
- 情報の非可逆圧縮（要約）をしない: 具体的な検討メモや作成した文案など重要と思われる情報は、「たぶん不要」と判断して削除せず、必ず含めること。情報を必要以上に短く省略しないこと
- 課題・エラー内容は原文を必ず含める: 直面している問題の詳細やエラーメッセージ等は要約・言い換えをせず、原文のまま引用すること
- 標準的なMarkdownを使用する: 見出しには必ず `#` や `##` などの標準Markdownを利用し、リストや箇条書きを用いて構造化すること
- 推測を含めない: 確定事項と未確認事項（推測）は明確に区別して記載すること
- 曖昧な表現を避ける: 次のチャット単体で再開できる粒度で記述する。「必要に応じて参照」のような丸投げ表現は使わない
- 作業関連の成果物を落とさない: 会話中に登場したプロンプト案・文案・構成案・企画内容なども漏れなく含める
- 引継ぎドキュメント（HANDOVER.md）作成後、内容のセルフチェック・レビューを行った上でユーザーへ報告する

</instructions>
