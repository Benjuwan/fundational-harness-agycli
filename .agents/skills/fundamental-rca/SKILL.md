# 根本的な再発防止対策 (Fundamental Root Cause Analysis)
**AIが明確なルール違反を犯した場合**、または**課題に対して多角的な視点・思考で取り組む必要がある場合**に、根本的・根源的な再発防止策を講じさせるためのスキルです。  
セッション記憶を持たないステートレスで、確率論に基づいた言語推論をしているだけのAIに「表層的な謝罪や言い訳」を許さず、ルール違反や課題に対する具体的な解決策を提示させるために利用します。

<instructions>

## 目的
本スキルの目的は、発生した問題（ルール無視、過剰推論、事前確認漏れなど）や課題に対しての**根本原因を論理的に深掘りし、具体的なアプローチや改善策をユーザーに対して提案する**ことです（AI自身によるファイルの直接編集は行わず、まずもって**根本調査と提案を主軸**とします）。

## 実行ワークフロー (Strictly sequential)
本スキルが発動した場合、AIは即座に以下のステップを順番に実行してください。

### Step 1: 表層的な謝罪の即時停止と原因究明への移行
- **行動**: 「申し訳ありません」「今後は徹底します」「以降は必ず守ります」といった精神論や建前のみで済まそうとする謝罪や言い訳を一切行わないこと。
- **宣言**: 「表層的な謝罪を停止し、根本的な再発防止策（Root Cause Analysis）の策定プロセスへ移行します。」と宣言する。

### Step 2: 根本原因の分析（5 Why / CoT / ToT思考）
- **行動**: 
  - **AIのルール違反の場合**： 今回なぜAIがルールを無視したのか？ その要因を言語化し、分析結果をユーザーに提示する。
  - **課題解決の場合**： どのような状態に落ち着けば課題解決となるのか「ゴール」を明確に定義し、そこから逆算して課題解決に必要な要素を抜け漏れなく列挙し、ユーザーにとって有益な提案ができるように論理的に深掘りする。
- **思考法**:
  - **5 Why（なぜなぜ分析）**: 「なぜそのミスが起きたか？ → ではなぜそのような判断をしたのか？ → ではなぜその情報を見落としたのか？」のように、事象に対して「なぜ？」を繰り返し問い詰め、表面的な理由ではなくシステム・プロンプト・環境構造の真因まで辿り着くこと。
  - **CoT (Chain of Thought)**: 「○○のルール違反を犯した / ○○でハマっている → □□が理由か？ → △△も怪しいのでは？ → ではなぜそう考えたのか？ → ××という状態であるため」と論理の連鎖を用いて原因を深掘りする
    - CoT の具体的なアプローチ例：
      - 段階的に情報を処理するよう誘導：「ステップ・バイ・ステップで考える」「途中の計算や推論も含めて記載する」など**一発で答えを出さずに深堀りしながら回答生成していく思考アプローチ**を実施する
  - **ToT (Tree of Thoughts)**: 複数の仮説（原因A、原因B、原因C）を立て、それぞれの可能性を検証・分岐させながら最も確からしい根本原因を特定する
    - ToT の具体的なアプローチ例：
        - 思考の枝を明示的に指示 : 「3つの解法パターンを提案」「それぞれのパターンについて順に深掘りする」といった**複数経路の思考ステップを実施**する
        - 評価ステップの設置 :「各案に対して利点と欠点を記述」「最終的に最も妥当な案を選出」というプロセスを取る
        - ステップの分割処理 : このような「まず3案出し → 次に評価 → 最後に結論」といった思考ステップを踏んで、可能な限り事実（ログやドキュメント）に基づき、最も確度の高い回答と解決策の提示に努める

このように、5 Why, Cot, ToTなどの思考アプローチを用いて客観的・多角的かつシステム的に原因を深掘りする。

### Step 3: 再発防止のためのアプローチ（改善策）の提案
- **行動**: 根本的・根源的解決につながる有効で具体的なアプローチを立案する。
- **改善策の評価基準**:
  - AIのコンテキスト（記憶領域）が圧迫された状態や、複雑なタスク実行時においても機能する仕組みになっているか？
  - 破壊的操作や重要タスクの実行前における「事前確認（Pre-Flight Check）」のプロセスとして組み込めるか？
- **検証の義務化**:
  - アドホックな対応となっていないか、考慮漏れや抜けは無いか、根本原因の解決につながる妥当な調査・分析結果となっているかを「検証サブエージェント（`qa-auditor.md`）」を起動して厳しく第三者チェックする。

### Step 4: 調査結果と改善案の提示
- **行動**: Step 3で作成した調査・分析結果と、再発防止に向けた具体的な改善アプローチ（ルールファイルの修正案やワークフローの見直し案など）をユーザーに提示する。
- **制約**: 本スキルでは調査と提案のみに留め、AI自身によるファイルの直接的な変更作業は行わないこと。

## 注意事項
- **問題がユーザー起因の場合も想定する**: 「プロンプトの具体性が不足している」「仕様の理解不足」などユーザー起因の場合は忖度せずに、その旨をユーザーに伝えて改善案の検討を提案すること。
- **そもそも本当に当該課題を解決する必要があるのか考える**: 費用対効果を加味し、初めから局所的な対応を採る前に「**そもそも論**」で俯瞰して思考することで最適な調査結果および提案の生成に努めること。
