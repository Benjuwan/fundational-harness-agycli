# レポートフォーマット・統合

本ファイルは、[SKILL.md](../SKILL.md) の Phase2（統合）・Phase3（提供）の詳細版です。レポート粒度は **厳密固定** とする。

---

## 1. Phase2: 統合の手順（メインエージェント）

各ペルソナの持ち帰り証拠を、単なる寄せ集めにせず以下の処理を行う。

1. **重複排除**: 同一箇所・同一原因の指摘を1件に統合する（証拠は集約して保持）。
2. **トライアンギュレーション**: 複数ペルソナが **独立に・証拠付きで** 同一指摘を挙げた場合は「高信頼」とマークする。
   - ※トライアンギュレーションの加点（高信頼マーク）は、解釈・体験に関わる指摘の独立一致に対して行う。**リンク切れ・コントラスト・属性欠落など機械的に検証可能な事実は、単一ペルソナ＋証拠で既に確実なため、複数ペルソナの重複検出を高信頼として加点しない**（重複作業による信頼度の水増しを防ぐ）。
3. **重大度で重み付け**: 影響範囲（全ページ/主要導線/局所）×深刻度（機能不全 > 到達阻害 > 品質低下 > 軽微）で優先度を決める。
4. **接地状態の明示**: 各指摘が「接地（証拠あり）」か「推論（免責ラベル）」かを保持する。

## 2. Phase3: 固定レポートフォーマット（5要素・厳密固定）

各改善仮説は、以下の5要素を **必ず** 備える。要素の省略・順序変更をしない。

> [!NOTE]
> 本フォーマットは設計ブリーフ 9-4 の4要素（優先度／根拠／インパクト・工数／推論注記）に **「裏取り」を加えた5要素構成**。トライアンギュレーション（複数ペルソナの独立一致）を可視化するため、ユーザー承認のうえ拡張した。

```
### [優先度: 高/中/低] <指摘の見出し（1行）>

- 改善仮説: <どう直すと何が改善するかの仮説（断定でなく仮説として提示）>
- 根拠（証拠）: <スクリーンショットのパス / DOM抜粋 / ログ抜粋>（接地必須の指摘は必ず添付）
- インパクト / 工数の目安: インパクト=<高/中/低>（理由） / 工数=<小/中/大>（理由）
- 推論注記: <接地不能な要素を含む場合のみ「【推論】…（実データではない）」を記載。含まなければ「なし」>
- 裏取り: <トライアンギュレーション有無（例: 3ペルソナが独立指摘＝高信頼 / 単一ペルソナ）>
```

### レポート冒頭に含める項目
- 対象サイト・サイト種別・分析目的（未指定なら「全体的な改善のとっかかり探索」）。
- 起動したペルソナ一覧（各1行の役割）と検証したページ範囲。
- **許容損失の明記**: 「CV関連ページは閲覧のみのため、フォーム入力時バリデーションUX等の実操作インサイトは対象外」。
