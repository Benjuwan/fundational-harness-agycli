# AIハーネス構築・カスタマイズガイド
〜定型業務の「スキル化」「ルール化」とAI利活用環境（盆栽）の育て方〜

本ガイドは、ナレッジワーカー（資料作成、データ整理、記事校正、Web管理などを行うビジネス担当者）が、生成AIを単なる「一問一答のチャットツール」から、自社・自身の業務に完全に最適化された**「AIパートナー（ハーネス環境）」**へと成長させるための実践的カスタマイズガイドです。

---

## 1. はじめに

### 本ガイドの目的（AI環境の「盆栽の剪定」）
生成AIを業務に導入する際、最初からすべてのルールや自動化仕組みを一から完璧に作り上げる必要はありません。AI環境の構築は、日々の業務を行いながら枝葉を整えていく**「盆栽の剪定・育込み」**に似ています。

- **初期状態**: 最上位の行動規範（`GEMINI.md`）と基本的な安全ルールのみが設定された状態
- **日常の運用**: 日々の定型業務（毎号のメルマガ執筆、週次データの集計、記事の校正など）を少しずつ切り出し、AIに手順を覚えさせる（スキル化）
- **継続的な剪定**: AIに同じ指摘を繰り返したらルール化（`rules/`）し、重い作業は専門AI（`agents/`）に分業させる

この小さな改善の積み重ねによって、AIはあなたやチームの「最高の相棒」へと育っていきます。

---

## 2. ハーネスを構成する要素と使い分け一覧

Antigravity環境（ハーネス）は、役割の異なる複数の構成要素で成り立っています。それぞれの特徴と適切な置き場所を把握することで、迷わず環境を拡張できます。

### 構成要素の比較表

| 構成要素 | 役割・イメージ | 適切な置き場所 | 導入・更新のタイミング |
| :--- | :--- | :--- | :--- |
| **最上位規範 (`GEMINI.md`)** | **憲法・基本姿勢**<br>AIが常に守るべき最上位の行動規範、事前承認（HITL）原則 | プロジェクトルート<br>`/GEMINI.md` | 初期セットアップ時（200行以内に抑えるのが推奨） |
| **ルール (`RULES`)** | **禁止事項・安全ガードレール**<br>「やってはいけないこと」「必ず守る制約」（過剰推論防止、機密保護等） | `.agents/rules/*.md` | 同じ指摘・注意を2回以上繰り返したとき |
| **スキル (`SKILLS`)** | **定型業務の手順書・ノウハウ**<br>特定タスクの具体的な遂行手順、フォーマット、ドメイン知識 | `.agents/skills/<skill-name>/SKILL.md` | 定型業務（週次レポート、校正等）をAIに任せたいとき |
| **サブエージェント (`SUB-AGENTS`)** | **専門役割を持つ別動AI**<br>メインの文脈を汚さず並列処理を行う特化型AI（実装、監査等） | `.agents/agents/*.md` | 大量のファイル調査や検証など、文脈を分離したいとき |
| **MCP (Model Context Protocol)** | **外部ツール・サービス接続**<br>ブラウザ操作（Playwright）、ドキュメント検索（Context7）等 | `.agents/mcp_config.json` | 外部Web・ブラウザ操作や最新ドキュメント検索が必要なとき |
| **フック (`HOOKS`)** | **イベント発火型自動スクリプト**<br>プロンプト送信直前やツール実行直前に自動実行される安全制御 | `.agents/hooks/`<br>グローバル `hooks.json` | コマンド実行の無言制御やルールの強制再注入を行いたいとき |

### コンポーネント選定フローチャート

```
新しい要件・ナレッジが発生した
  │
  ├─ プロジェクト全体の基本姿勢・絶対遵守事項か？
  │     └→ 【GEMINI.md】に記述（憲法）
  │
  ├─ 特定の作業における禁止事項・注意事項・安全制約か？
  │     └→ 【.agents/rules/】に独立ファイルとして作成
  │
  ├─ 特定の定型業務の手順・成果物フォーマット・ノウハウか？
  │     └→ 【.agents/skills/】にスキルを作成（手順書）
  │
  ├─ メインのチャットの記憶（コンテキスト）を消費せず、専門のAIに独立して並列作業させたいか？
  │     └→ 【.agents/agents/】にサブエージェントを作成（専門員）
  │
  ├─ ブラウザ操作や外部データベース・最新ドキュメントの検索が必要か？
  │     └→ 【.agents/mcp_config.json】にMCPを追加（外部連携）
  │
  └─ AIの実行ループ（LLM呼び出し前後・ツール実行前後）に自動制御を割り込ませたいか？
        └→ 【.agents/hooks/】および【hooks.json】でフックを設定（自動制御）
```

## 3. ステップバイステップ: 最初のスキル（定型業務の手順書）を作る

スキル（`SKILL.md`）は、AIに「特定の業務をどうこなすか」という専門知識と手順を授ける仕組みです。

### (1) 一から書かない！壁打ちスキル（`grill-me`）を活用した自動ドラフト作成

ナレッジワーカーがスキル定義ファイル（YAMLやMarkdown）を一から手書きする必要はありません。本ハーネスに同梱されている壁打ちスキル **`grill-me`** を使い、AIからの質問に答えるだけでスキルを自動生成できます。

#### 実践手順

1. **チャットで `grill-me` を呼び出す**:
   プロンプトに以下のように入力します。
   ```text
   @grill-me 毎週行っている「競合他社のWebニュースまとめ記事の作成業務」をスキル化したいので、ヒアリングしてください。
   ```
2. **AIからの逆質問に回答する**:
   AIが以下のような質問を投げかけてきます。
   - 情報収集元のWebサイトやURLはどこか？
   - 記事のターゲット読者とトーン＆マナーは？
   - 成果物の見出し構成や文字数の制限は？
   - 避けるべき表現や禁止事項は何か？
3. **スキルの自動作成を依頼する**:
   やり取りが完了したら、「この内容で `.agents/skills/competitor-news-summary/SKILL.md` を作成してください」と指示します。

> [!TIP]
> **壁打ち（ヒアリング）のメリット**
> 人間が一人で考えると言語化し忘れる「暗黙の了解（例外処理やNG表現）」を、AIが鋭い質問で引き出してくれるため、抜け漏れのない高品質な手順書が完成します。

---

### (2) `SKILL.md` の基本構造と書き方のコツ

完成した `SKILL.md` は以下のような構成になっています。

```markdown
---
name: competitor-news-summary
description: 競合他社の最新ニュース記事を収集し、社内共有用の要約レポートを作成する際に使用する。Web検索や記事要約の依頼があった場合に発動。
---

# 競合ニュース要約スキル

本スキルは、競合他社のWebサイトやニュースから主要トピックを抽出し、社内向け要約レポートを作成するための手順書です。

<instructions>
## 絶対に守るべき作業手順

1. **情報収集**:
   - 指定されたURLまたはキーワード（「業界名 プレスリリース」等）で最新情報を確認する。
2. **要約と構造化**:
   - 各記事について「タイトル」「概要（100文字）」「自社への影響」の3要素で整理する。
3. **品質チェック・禁止事項**:
   - 未確認の噂や根拠のない推測は記載しない。
   - 機密情報や競合の不確定要素を断定的に書かない。
</instructions>
```

#### ① `description` の書き方の極意（発火精度の向上）
フロントマターの `description` は、AIが**「今このスキルを使うべきかどうか」を自動判断（暗黙的呼び出し）する際の唯一の基準**になります。

- **いつ使うべきか（トリガー条件）** を明確に書く
- **いつ使うべきでないか（境界条件）** を記載する
- **200文字以内** で具体的に記述する

> [!NOTE]
> **良い例**: `競合他社のニュースやWeb記事の要約レポートを作成する際に使用する。単なる一般的な文章校正や自社ブログ執筆時には使用しない。`  
> **悪い例**: `ニュース要約のスキルです。` （抽象的すぎてAIがいつ使えばいいか判断できない）

#### ② `<instructions>` タグの活用（最優先遵守の強制）
スキルの指示文の中で、**「AIに絶対に守らせたい厳格な手順やルール」** は `<instructions>` 〜 `</instructions>` タグで囲みます。

Antigravity CLI は、このタグに囲まれた内容を **「専門的な手続きのガイダンス（expert procedural guidance）」** として認識し、AIの一般的な基本ルールよりも優先して厳格に守ろうとします。AIの自律的な暴走や手順の省略を防ぐために非常に効果的です。

---

### (3) 明示的呼び出しと暗黙的呼び出しの仕組み

スキルを実行する方法には「暗黙的呼び出し」と「明示的呼び出し」の2種類があります。

```
スキルの呼び出し方法
  │
  ├─ 暗黙的呼び出し（AIによる自動判断）
  │     └→ ユーザー「競合の最新ニュースをまとめて」
  │           └→ AIが description を見て activate_skill で自動起動
  │
  └─ 明示的呼び出し（ユーザーによる直接指定）
        ├─ プロンプト内指定: @competitor-news-summary 最新ニュースをまとめて
        └─ チャットUIコマンド: /competitor-news-summary
```

- **暗黙的呼び出し**: ユーザーの自然な発言から、AIが `description` を読み取って自動的にスキルを起動します。
- **明示的呼び出し**:
  - **`@skill-name`**: プロンプト内で直接スキル名を指定して強制的・確実に適用させます。
  - **`/<skill-name>`**: チャットUIのスラッシュコマンドとして即座に実行します。

## 4. ステップバイステップ: ルール・サブエージェントへの拡張

定型業務のスキル化に慣れてきたら、さらに環境を強化するために「ルール（`rules/`）」と「サブエージェント（`agents/`）」へ拡張していきましょう。

### (1) 繰り返される指摘・禁止事項を `rules/` に切り出す

AIと作業していて「前も同じ注意をしたな」と感じたら、それはルール化のサインです。

#### 切り出しの基準
- 同じ修正指示や指摘を **2回以上** 受けた場合
- 個人情報の漏洩防止やファイル削除の禁止など、**絶対防ぎたいリスク** がある場合

#### 推奨ルールファイルの例 (`.agents/rules/` 配下)
- **`over-engineering-prevention.md`**: 指示されていない周辺ファイルやコードの勝手な改修（過剰推論）を禁止する。
- **`hitl-policy.md`**: ファイルの大幅な書き換えや新規作成前に、必ず人間に「y/n」で確認（事前承認）を求める。
- **`minimal-security-guidelines.md`**: `.env` や認証情報など機密データの漏洩・ログ混入を防止する。
- **`output-quality-guidelines.md`**: ビジネス文書作成・要約・レビューにおける品質基準を維持する。

> [!TIP]
> **ルールのモジュール化**
> ルールを1つのファイルに全部書くと長くなり、AIが途中で忘れてしまいます（Lost in the Middle現象）。「1ファイル1テーマ」で分割して管理するのがポイントです。

---

### (2) メインの文脈を汚さず並列処理を行うサブエージェント（`agents/`）

サブエージェントとは、メインのAIチャットとは独立した「別の専門AI」を起動して作業を行わせる仕組みです。

#### なぜサブエージェントが必要なのか？
1つのチャットセッションで大量のファイル読み込みやデータ検索を行うと、記憶容量（コンテキストウィンドウ）が埋まり、AIが初期指示やルールを忘れてしまいます。

サブエージェントを活用することで、**メインの会話の記憶を綺麗に保ったまま、重い作業や専門的な調査を別動隊に任せる**ことができます。

#### 本環境の推奨サブエージェント例 (`.agents/agents/` 配下)
- **`implementer-agent`**: 指示された手順に厳格に従い、余計な改修をせずに正確に資料やコードを作成する専門員。
- **`task-executor`**: メインAIの指示に基づき、タスクの細分化・自律実行・セルフレビューを行う実行専門員。
- **`qa-auditor`**: 完成した成果物（Webページ、ドキュメントなど）に抜け漏れや矛盾がないか第3者視点で検証する専門員。
- **`image-processor`**: 画像のリサイズやフォーマット変換などのスクリプト処理を自律的に行う専門員。

```
メインエージェント（進行管理・会話）
  │
  ├─→ [invoke_subagent] → implementer-agent（資料・コード作成を実行）
  │                             │ (完了報告)
  │                             ▼
  └─→ [invoke_subagent] → qa-auditor（成果物を独立監査・チェック）
                                │ (PASS報告)
                                ▼
                       ユーザーへ最終完了報告
```

> [!CAUTION]
> **【要注意】カスタムサブエージェント呼び出し時の「ツール剥奪トラップ」と「`self` 憑依アプローチ」**
> 
> Antigravity CLI でサブエージェントを運用する際、システムの制約に関する極めて重要な注意点（仕様トラップ）が存在します。
> 
> #### 1. ツール剥奪トラップとは？
> `invoke_subagent` ツールでカスタムサブエージェント名（例: `implementer-agent` や `qa-auditor` など）を直接指定して起動すると、システム側の権限制御・ツール制限により、**`view_file`（ファイル閲覧）や `run_command`（コマンド実行）といった必須ツールがサブエージェントに一切付与されず剥奪されてしまう現象（ツール剥奪トラップ）**が発生します。
> この状態に陥ると、サブエージェントは手足をもがれた状態となり、ファイル閲覧も編集も行えずタスクが完全に停止してしまいます。
> 
> #### 2. `self` 憑依（オーバーソウル）アプローチによる解決
> この仕様トラップを回避し、サブエージェントに全ツール権限を持たせた状態で専門役割を実行させるための唯一確実な手法が**「`self` 憑依（オーバーソウル）アプローチ」**です。
> 
> - **原理**: 全ツール権限を親から完全継承する組み込みサブエージェント **`self`** を起動対象（`TypeName: "self"`）として指定し、その初期プロンプト内に `.agents/agents/<対象エージェント名>.md` の専門役割定義を注入（憑依）させて起動します。
> - **具体的な手順（プロンプト生成スクリプトの利用）**:
>   1. 直近の業務コンテキストや引き継ぎ指示書（`tasks/HANDOVER.md` 等）を用意します。
>   2. 統合スクリプト（`utils/generate_subagent_prompt.py`）を実行し、対象サブエージェントの定義ファイルと指示書を統合した初回指示プロンプトを生成します。
>      ```bash
>      python3 utils/generate_subagent_prompt.py implementer-agent tasks/HANDOVER.md
>      ```
>   3. スクリプトが出力した統合プロンプト文字列をそのまま改変せずに、`invoke_subagent` の `TypeName: "self"` に渡して起動します。
> 
> このアプローチにより、サブエージェントは `view_file` や `run_command` などの必須ツールを100%保持した状態で、専門エージェントとしての高度なタスクを自律完遂できるようになります。

## 5. 補足: MCP と フック（Hooks）の位置付け

さらに高度な連携・制御を行うためのコンポーネントとして「MCP」と「フック（Hooks）」が存在します。

### (1) MCP と スキル (SKILL) の違いと選定基準

| 項目 | SKILL (スキル) | MCP (Model Context Protocol) |
| :--- | :--- | :--- |
| **仕組み** | プロンプトへの**静的な知識・手順の注入** | 外部ツール・プログラムとの**動的な連携規格** |
| **処理コスト** | 非常に軽量（プロンプト読み込みのみ） | 高め（ツール検出・スキーマやり取りが発生） |
| **得意なこと** | 業務手順、レポートフォーマット、定型作業 | 実際のブラウザ操作、DB接続、最新API検索 |
| **例** | `presentation-slider-creator`, `grill-me` | `playwright-mcp` (ブラウザ自動化), `context7` |

#### 選定の目安
- 手順やフォーマットの指示で完結する作業 → **SKILL** を選択（低コスト・高速）
- 実際にブラウザを開いて画面を操作・確認したり外部サービスと通信する作業 → **MCP** を選択

> [!TIP]
> **CLIツール（`@playwright/cli` 等）との使い分け**
> `playwright-mcp` はAIが画面構造（アクセシビリティツリー）をじっくり探索しながら操作するのに向いていますが、トークン消費が多くなります。単に決まったページを操作・テストしたい場合は、`@playwright/cli` などのCLIツールをSKILL経由で呼び出す方がトークンを大幅に節約できます。

---

### (2) フック（Hooks）による自動制御の仕組み

フックとは、AIの動作ループ（プロンプトを送信する直前、コマンドを実行する直前など）に自動で割り込み、カスタムスクリプトを実行する仕組みです。

```
ユーザーがプロンプト入力
  │
  ▼
【PreInvocation フック】 (例: 最優先ルールや現在時刻の自動注入、セッション警告)
  │
  ▼
AIがコマンド実行を計画
  │
  ▼
【PreToolUse フック】 (例: 無言コマンド実行のブロック・事前説明の強制)
  │
  ▼
コマンドの実際の実行
```

- **`PreInvocation`**: AIへメッセージを渡す直前に、最新のルールや追加情報を自動インジェクトする。
- **`PreToolUse`**: AIがコマンドを無言で実行しようとした際、実行を一時ブロックして日本語での事前説明を強制する（事故防止）。

フックの詳細な設定手順や同梱スクリプトの活用方法については、以下のガイドを参照してください。

👉 [**フック（Hooks）初期設定・運用ガイド**](./hook-setup-guide.md)

## 6. まとめ: 自分だけの「AIハーネス」を育てるロードマップ

AI環境のカスタマイズは、一度に行う必要はありません。以下のロードマップに沿って、段階的に「自分専用のAIハーネス」へと育てていきましょう。

```
【ステップ1: 基礎セットアップ】
  └─ GEMINI.md と基本ルール、必須MCP（playwright, context7）を設置
     (詳細は [初期セットアップガイド](./init-setup-guide.md) を参照)
        │
        ▼
【ステップ2: 最初のスキル作成】
  └─ 壁打ちスキル (@grill-me) を使って、日々の定型業務を1つ「SKILL.md」化する
        │
        ▼
【ステップ3: ルールの蓄積と分業】
  └─ AIへの注意・指摘を「.agents/rules/」へ切り出し、重い作業はサブエージェントへ委譲
        │
        ▼
【ステップ4: フックによる安全自動化】
  └─ フック (Hooks) を導入し、無言操作のブロックや記憶の自動維持をシステム的に強制
```
