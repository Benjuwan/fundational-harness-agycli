# Antigravity CLI / IDE 活用・併用ガイド
本ドキュメントは、ナレッジワーカーや開発者が Antigravity CLI (`agy`) と Antigravity IDE の双方の強みを最大限に活かし、スムーズかつ安全に業務を進めるための併用スタイル、便利なコマンド活用術、事故防止ルール、およびキーバインド競合の解決策をまとめたガイドです。

## 1. はじめに
生成AIエージェント環境である Antigravity には、ターミナル上で高度な自律処理や並列タスクを行う **Antigravity CLI (`agy`)** と、エディタ上でコード編集やリアルタイム調整を行う **Antigravity IDE** の2つのインターフェースが存在します。  
本ドキュメントの目的は、これら2つのツールの強みを掛け合わせ、ファイル同期エラーやコンテキスト（文脈）分断といったトラブルを防ぎながら、快適な並行・協業スタイルを確立することです。

> [!TIP]
> 初めて環境を構築する方や、基本設定・権限管理・MCP導入について確認したい方は、まず [初期セットアップガイド](./init-setup-guide.md) を参照してください。

## 2. CLI と IDE の併用スタイル（役割分担）
状況や作業の性質に応じて、CLI と IDE のどちらを「主」とするか、あるいはクラウド実行環境を組み合わせるかを使い分けることで、作業効率が飛躍的に向上します。

### (1) CLI 主導スタイル
- **概要**: 複雑な多段階処理やファイルの一括生成・大枠の実装を Antigravity CLI に指示し、生成されたコードの細かな調整やUI修正を Antigravity IDE で行うスタイルです。
- **具体例**:
  1. CLI で「〇〇機能の基本構造とテストコードを一括生成して」と指示し、ベースコードを作成。
  2. IDE でファイルを開き、Gemini Code Assist と対話しながらロジックの微調整やUIレイアウトの調整を実施。
- **メリット**: 思考のスピードを損なわずに大枠を構築でき、手作業での細かなフィードバックもスムーズに行えます。

### (2) IDE 主導スタイル
- **概要**: 通常のエディタ作業（IDE）を中心に進め、定型ファイルの作成や一括データ加工、重い検証作業など「まとまった定型タスク」が発生した際に CLI でカバーするスタイルです。
- **具体例**:
  1. IDE 上で新機能のコアロジックを実装。
  2. 関連するダミーデータ作成や、複数ファイルにわたる定型ドキュメントの更新を CLI に任せる。
- **メリット**: エディタ中心の慣れた作業リズムを維持しつつ、定型作業の負担を削減できます。

### (3) クラウド非同期（Jules）との連携
- **概要**: ローカルでの本筋の開発から独立した Issue（バグ修正、テスト追加、リファクタリングなど）を、全自動のクラウド実行環境「Jules」にアサインして非同期処理させるスタイルです。
- **具体例**:
  - 自分がメイン機能の開発に集中している裏側で、Jules に「〇〇関数の単体テストを追加してPRを作成しておいて」と指示。
  - クラウド上で「ブランチ作成 → 実装 → テスト実行 → コミット → GitHubへのPR作成」までが全自動で完了。
- **メリット**: レビュー待ちや Git 操作の手間を省き、メイン作業の手を止めることなくバックグラウンドで開発を並行処理できます。

## 3. 日常業務を円滑にするCLIコマンド活用術
Antigravity CLI のチャット入力欄では、AIのタスク進行管理やセッションの制御を行うネイティブな「スラッシュコマンド」が利用できます。

### 主要スラッシュコマンド一覧と活用シナリオ

| コマンド | 機能概要 | おすすめの活用シナリオ |
| :--- | :--- | :--- |
| **`/rewind`** | 直前の指示を取り消し、ファイルの変更やツール実行を1歩前の状態に戻す | 「指示の意図がうまく伝わらず、意図しないファイル変更が行われてしまったので直前に戻したい」とき |
| **`/clear`** | チャット画面と会話履歴（コンテキスト）をすべてリセットする | 「1つのタスクが完了し、全く別の新しい話題・タスクに移りたい」とき（過去の履歴によるノイズを防止） |
| **`/btw`** | メインの会話文脈を汚さずに、一時的な質問や寄り道を行う（By The Way） | 「メインの実装途中で『このエラーコードの意味だけ教えて』とちょっとした質問を挟みたい」とき |
| **`/fork`** | 現在の会話履歴を維持したまま、別ルートの独立セッションとして分岐する | 「現在のコード状態から、破壊的なリファクタリングや別のアプローチを実験的に試したい」とき |
| **`/tasks`** | 実行中のバックグラウンドタスクの監視・ログ表示・終了 | 「裏で動かしているテストやサーバーの実行状態を確認・停止したい」とき |
| **`/permissions`** | エージェントの自律レベル（request-review, always-proceed 等）を変更 | 「信頼できる定型作業なので、都度承認なしで一気に進めさせたい」とき |
| **`/goal`** | 目的が完全に達成されるまで、エージェントに徹底的に作業を継続させる | 「夜間や離席中に、時間のかかる調査やテスト作成を最後まで完遂させたい」とき |
| **`/schedule`** | 定期的なスケジュール実行やタイマー起動をセットする | 「1時間後にヘルスチェックを実行したい」「毎朝定時にレポートを作成したい」とき |
| **`/plan`** | 事前に詳細な計画書（プラン）を策定させ、承認を得てから実行させる | 「大規模なコード修正や、慎重に進めたい複雑なタスクを開始する」とき |
| **`/config`** | サンドボックスやツール実行権限、テーマなどの設定画面を開く | 「CLI の動作設定やテレメトリ（学習オプトアウト）の設定を変更したい」とき |
| **`kill_all`** | 起動中のローカルサーバーやサブエージェント等をすべて強制終了する | 「検証用の開発サーバーやバックグラウンドプロセスをまとめて停止したい」とき |

> [!TIP]
> **文脈（コンテキスト）の保護・分岐コマンドの使い分け**
> - **`/btw`（寄り道）**: 同一セッション内でメイン文脈を汚さずにサブ質問を行う（完了後にすぐ元の文脈へ戻れる）。
> - **`/fork`（実験分岐）**: 過去の履歴を引き継いだ別セッションを立ち上げ、失敗しても元セッションに影響を与えずに別アプローチを実験する。

## 4. 事故を防ぐ運用ルール（コンフリクト & 文脈分断の防止）
CLI と IDE を併用する際、最も発生しやすいトラブルが「ファイル同期の競合（コンフリクト）」と「AI間の文脈（コンテキスト）分断」です。以下のルールを徹底してください。

### (1) ファイル同期競合の防ぎ方
- **リスク**: IDE 上で未保存のファイルを開いたまま、裏で CLI に同じファイルを書き換えさせた場合、IDE の未保存内容と CLI の変更が衝突し、コードが先祖返り・破棄される恐れがあります。
- **運用ルール**:
  1. **事前保存・コミット**: CLI に大きめの変更やファイル編集を指示する際は、必ず **IDE 上の対象ファイルを保存して閉じる** か、**Git でコミット** しておく習慣をつけてください。
  2. **自動保存の有効化**: IDE 側の設定で `files.autoSave` を有効化しておくことも有効です。

### (2) AI間のコンテキスト共有 (`HANDOVER.md` 運用)
- **リスク**: IDE に組み込まれた AI (Code Assist) と、ターミナルで動く Antigravity CLI は、会話履歴や文脈を直接共有していません。そのため、片方で進めた作業内容をもう片方が把握できず、行き違いが発生します。
- **運用ルール**:
  - プロジェクトルートに引き継ぎドキュメント **`HANDOVER.md`** を設置し、タスクの進捗状況を共有します。

> [!WARNING]
> **`HANDOVER.md` 記述時の重要ポイント**
> `HANDOVER.md` に「過去に作ったもの（過去のコードや変更履歴）」を詳しく書きすぎると、コード自体との二重管理となり、AIのコード検索時に古いバージョンの情報がヒットしてノイズになります。
> `HANDOVER.md` には **「現在の進捗」と「これから作るもの（未完了タスク）」のみを簡潔に記録** してください。

## 5. トラブルシューティング: キーバインド（ショートカット）競合の解消
IDE 内の統合ターミナルで Antigravity CLI を実行すると、IDE 側のキーボードショートカットが横取りされ、CLI 側の操作（承認用の `Ctrl + K` や削除用の `Ctrl + D` など）が効かない場合があります。

### (1) IDE 統合ターミナルのキー入力通過設定
IDE 側のキー割り当てがターミナルイベントを遮断するのを防ぐ設定です。

1. `Ctrl + Shift + P` (Mac は `Cmd + Shift + P`) でコマンドパレットを開きます。
2. **`基本設定: ユーザー設定を開く (JSON)`** (`Preferences: Open User Settings (JSON)`) を選択します。
3. 設定ファイルに以下を追加して保存します：

```json
{
  // ターミナルフォーカス時にIDEのショートカット（Chords）を無効化し、直接CLIにキーを渡す
  "terminal.integrated.allowChords": false
}
```

### (2) 会話履歴削除・ターミナルキーバインド設定 (Windows OS / IDE環境)
Antigravity CLI 内で `/resume` コマンド等を使用した際、会話履歴の削除（`Ctrl + Delete`）やセッション終了操作が正常に機能しない場合の解決手順です。

#### IDE 側の設定 (`keybindings.json`)
コマンドパレットから **`基本設定: キーボードショートカットを開く (JSON)`** を開き、以下を設定します：

```json
[
  {
    // デフォルトの会話開始ショートカットを無効化
    "command": "-antigravity.startNewConversation",
    "key": "ctrl+shift+l"
  },
  {
    // Ctrl + Delete をターミナル内の削除シーケンスとして送信
    "command": "workbench.action.terminal.sendSequence",
    "key": "ctrl+delete",
    "args": {
      "text": "\u001b[3;5~"
    },
    "when": "terminalFocus"
  }
]
```

#### Antigravity CLI 側の終了キー変更
CLI の終了ショートカット（デフォルト: `Ctrl + D`）が他機能と衝突して誤終了するのを防ぐため、設定を変更します。

- **対象ファイル**: `~/.gemini/antigravity-cli/keybindings.json`
- **変更内容**:

```diff
- "cli.exit": ["ctrl+d"],
+ "cli.exit": ["ctrl+q"],
```

これにより、`Ctrl + Q` で安全に CLI を終了できるようになり、ターミナル内での意図しない切断を防ぐことができます。
